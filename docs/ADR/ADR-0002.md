# ADR 0002 — Target GPU and Toolchain

## Status

Accepted

## Context

MiniRT v0.1 requires one fixed GPU and development toolchain so that CUDA compilation, supported features, profiling results, and performance measurements have a single reproducible reference environment.

Supporting multiple GPU generations or toolchains is outside the v0.1 scope.

## Decision

MiniRT v0.1 targets the following hardware:

```text
GPU: NVIDIA GeForce RTX 2060 SUPER
GPU architecture: NVIDIA Turing
Compute capability: 7.5
CUDA target architecture: sm_75
GPU memory: 8192 MiB
Host memory: 16 GiB
```

CMake must compile CUDA device code for:

```text
CMAKE_CUDA_ARCHITECTURES=75
```

The reference development environment is:

```text
Operating system:
  Fedora Linux 43
  KDE Plasma Desktop Edition

NVIDIA driver:
  580.126.18

CUDA Toolkit:
  13.2
  nvcc 13.2.51

Host compiler:
  GCC 15.2.1

CMake:
  4.2.3

C++ standard:
  C++17
```

## Driver / Toolkit compatibility

`nvidia-smi` reports CUDA 13.0 support for the installed NVIDIA driver, while the installed CUDA Toolkit is 13.2.

The current driver belongs to the CUDA 13.x minor-version compatibility range.

A compile-and-run CUDA smoke test is required before the toolchain contract is considered validated.

If CUDA 13.2 functionality required by MiniRT fails because of driver compatibility, the preferred options are:

1. upgrade the NVIDIA driver while keeping CUDA 13.2; or
2. use a CUDA Toolkit version compatible with the installed driver without minor-version compatibility.

The project must not silently change either component.

## Compilation policy

Release and profiling builds target only `sm_75`.

Example CMake configuration:

```cmake
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

set(CMAKE_CUDA_STANDARD 17)
set(CMAKE_CUDA_STANDARD_REQUIRED ON)

set(CMAKE_CUDA_ARCHITECTURES 75)
```

Supporting additional SM architectures is not required for v0.1.

## Performance policy

All MiniRT v0.1 performance claims are specific to:

```text
RTX 2060 SUPER
Turing / sm_75
```

Benchmark results must record at least:

```text
GPU model
compute capability
driver version
CUDA Toolkit version
host compiler version
CMake version
operating system
build type
CUDA architecture
git revision
```

Results obtained on another GPU must not be presented as directly comparable v0.1 target-GPU results without explicitly identifying the different environment.

## Hardware constraints

The target development machine has:

```text
GPU memory: 8 GiB
Host memory: 16 GiB
```

MiniRT must therefore keep ordinary correctness and development workloads small.

A generated TinyModel is used for fast end-to-end tests.

The real target model may be used for real-shape benchmarks and integration tests when memory permits.

## Non-goals

MiniRT v0.1 does not require:

* support for Ampere, Ada, Hopper, or Blackwell;
* support for multiple GPU architectures;
* multi-GPU execution;
* distributed execution;
* architecture-independent performance claims;
* automatic SM-specific backend dispatch.

## Consequences

Advantages:

* kernels have one concrete optimization target;
* profiler results are comparable across experiments;
* CUDA architecture assumptions remain explicit;
* benchmark results have a well-defined reference environment.

Limitations:

* results are specific to an older Turing GPU;
* kernels optimized for SM75 may not be optimal on newer GPUs;
* some modern CUDA data types and hardware features are unavailable;
* support for newer GPUs will require separate validation and potentially separate optimized backends.

## Verification

Record the output of:

```bash
nvidia-smi
nvcc --version
cmake --version
g++ --version
cat /etc/os-release
```

Then compile and run a minimal CUDA program for `sm_75`.

The smoke test must:

1. detect the RTX 2060 SUPER;
2. report compute capability 7.5;
3. allocate device memory;
4. launch a CUDA kernel;
5. synchronize successfully;
6. copy and validate the result.

No GPU/toolchain field may remain `TBD` before CUDA kernel development begins.
